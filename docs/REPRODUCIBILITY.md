# Main-method reproduction protocol

The recorded software stack is Python 3.10, NumPy 2.2.6, pandas 2.3.3,
PyArrow 23.0.1, SciPy 1.15.3, scikit-learn 1.7.2, LightGBM 4.6.0, and
FAISS 1.10.0.

All commands below are run from the repository root.

The complete pipeline can be run through one entry point. With no arguments it
uses the included compact example; the full-workload form is shown in the README.

```bash
python run_pipeline.py
```

## 1. Prepare vectors

Place the MTEB query and document vector exports below one vector root. The
77 expected dataset/model exports, revisions, run IDs, dimensions, and row
counts are listed in `configs/vector_manifests.json`.

## 2. Build HNSW indexes

```bash
python pipeline/01_build_indexes/build_hnsw_indexes.py \
  --vector-root /path/to/vector/root \
  --lock configs/vector_manifests.json \
  --output-root artifacts/hnsw \
  --threads 1
```

This builds 16 indexes per dataset/model pair using the grid in the README and
saves each FAISS index for the next stage.

## 3. Measure per-query search cost

```bash
python pipeline/02_measure_query_costs/measure_query_costs.py \
  --hnsw-root artifacts/hnsw \
  --output-root artifacts/query_costs \
  --workers 1 \
  --faiss-threads 1
```

The script runs every query separately at seven `efSearch` values, resets the
FAISS statistics immediately before each search, and records the query-level
`ndis` counter used as the model target.

## 4. Compute query features

```bash
python pipeline/03_extract_query_features/compute_query_features.py \
  --vector-root /path/to/vector/root \
  --lock configs/vector_manifests.json \
  --output-root artifacts/query_features
```

The 16 features are computed once for each dataset/model/query key. Their
definitions are implemented in `src/hnsw_cost/features.py` and explained in
`docs/FEATURE_DEFINITIONS.md`.

## 5. Build the training table

```bash
python pipeline/04_build_training_table/build_training_table.py \
  --labels-root artifacts/query_costs \
  --features-root artifacts/query_features \
  --lock configs/vector_manifests.json \
  --output data/training_table.parquet
```

The resulting Parquet contains the measured label, the three HNSW settings,
`num_docs`, and the 16 query features. Each query feature row is joined to its
112 HNSW settings using `(dataset, model_slug, query_offset)`.

## 6. Train and evaluate

`run_pipeline.py` runs every joint dataset/model holdout, merges the predictions,
and checks the fold and row counts derived from the training table. The worker
enforces the joint held-dataset and held-model split,
fits missing-value medians on training rows only, and uses the fixed seed and
LightGBM settings in the repository.

## 7. Build result tables

The unified runner calls `summarize_ablation.py` and
`compute_within_setting_kendall.py`, then writes the two compact final tables.

Exact wall time varies by hardware. The paper's recorded timing data are kept
in `results/efficiency/timing.csv`; they are not regenerated by the compact
example. Dataset/model revisions, row counts, HNSW settings, fold identities,
and metric formulas must remain fixed when reproducing the full experiment.
